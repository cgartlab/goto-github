# 判定标准 — GitHub 连通性分级

Phase 2 的唯一权威判据。SKILL.md 不复述这些数字。

## 端点清单（固定 5 个，不可增减）

| key | URL | 走这条路径的东西 |
|---|---|---|
| `web` | `https://github.com/` | 浏览器访问、网页前端 |
| `api` | `https://api.github.com/` | REST API、`gh` CLI |
| `download` | `https://codeload.github.com/<repo>/tar.gz/refs/heads/main` | tarball/zip 下载 |
| `raw` | `https://raw.githubusercontent.com/...` | raw 文件、部分 CDN |
| `git` | `https://github.com/<repo>/info/refs?service=git-upload-pack` | clone / fetch / push |

**为什么固定这 5 个**：覆盖 GitHub 的全部独立路径（前端、API、下载、raw、git 协议）。增减任何一个都会让"分级"失真——少测一个端点就可能漏掉真实退化。阈值是对这 5 个端点定义的，换成别的端点阈值不成立。

**为什么探测必须绕代理**：`--noproxy '*'`（curl）或清空代理配置。代理开启时测的是代理质量，不是本机→GitHub。实测过代理开着时的"成功"完全不可归因。

## 阈值

| 分级 | 条件 | 结论 |
|---|---|---|
| `direct_ok` | `git` ≥ 85% **且** `api` ≥ 85% | 直连可用，不用改 hosts |
| `hosts_needed` | `git` ≥ 85% **或** `api` ≥ 85%，但 `web` < 60% | hosts 加速有实际收益 |
| `partial_degraded` | `git` 或 `api` 在 50%–85% | 间歇可用，hosts 可能改善，先说明再动 |
| `proxy_needed` | `git` < 50% **且** `api` < 50% | 不建议 hosts，建议代理 |

阈值依据（本机实测 3 轮 × 10 次/端点）：

- `git` 与 `api` 在直连环境下从未低于 85%（3 轮分别 85%/70%/100%、100%/100%/100%）。低于此说明环境本身有问题。
- `web` 在直连环境下可低至 30%，且与 `git` 同 IP——**按路径干扰的直接证据**。所以 `web` 单独设阈值，不与 `git` 合并。
- 全端点 < 50% 时，hosts 改变的是域名→IP 映射，对整体阻断或路径级封锁无效。

## git 端点权重最高的理由

clone / fetch / push 全部走 git smart-HTTP，`gh` 与 CI 全部走 api。这两个可用 = "开发用途可用"。网页退化只影响浏览器浏览体验，不影响任何开发动作。

**因此报告禁止把 5 个端点合并成一个"GitHub 可用/不可用"结论。** 必须分端点列出成功率，再给分级。

## 单次结果不是证据

同一端点在 1 分钟间隔内的两次 10 次采样可以差 30 个百分点（实测 `web` 60% → 30%，`git` 100% → 70%）。所以：

- 判定只用成功率，不用单次成败。
- 默认 10 次采样；少于 5 次时报告必须标注 `sample_size` 并说明"样本不足，判定不稳"。
- 复测（Phase 3 后）必须用与 Phase 1 相同的 `--attempts`，否则前后不可比。

## 改善的噪声阈值

`hosts_status --baseline` 判定"是否改善"时，端点成功率必须**高出基线至少 10 个百分点**才算改善。

理由：采样噪声本身就能产生 1–2 个百分点的波动（实测 99% → 100% 纯属偶然）。把这种波动计为"修复生效"会让 `partial` 泛滥——而那正是 baseline 对比要避免的假阳性。

因此 `fixed` 的完整条件是：`web` ≥ 60% **且** 至少一个端点高出基线 ≥ 10 个百分点 **且** `git`/`api` 均 ≥ 85%。

## 采样时延也要报

成功率之外输出 min/max/avg：

- 成功但慢（avg > 3s）→ 报告"可用但体验差"，这与"不可用"是不同的结论。
- max 远高于 avg（如 avg 0.8s 而 max 6s）→ 尾部延迟差，间歇性丢包的典型形态。

## 时变干扰

实测两轮间隔仅数分钟，成功率出现 30 个百分点波动。结论必须带时间戳；用户拿几小时前的结论当现状是误用。复测永远优先于引用旧数据。
